# DATA — 데이터 출처와 재현

저장소에는 **원본 데이터가 포함되지 않습니다.** 재배포 조건이 확인되지 않은 공공데이터이고,
용량도 약 143MB라 Git 으로 관리할 대상이 아니기 때문입니다.

이 문서는 무엇을 어디서 받아 어디에 두면 파이프라인이 그대로 재현되는지 설명합니다.

---

## 1. 저장소에 포함한 것 / 제외한 것

| 경로 | 포함 | 사유 |
|---|---|---|
| `data/master/**` | ✅ | 프로젝트 정의 그 자체. 범위·환승역·분기점·이벤트 캘린더·노선도 좌표 |
| `reports/**/*.md`, 요약 `.csv`, `figures/*.png` | ✅ | 실행 결과 검증 증거 |
| `scripts/`, `app/`, `tests/`, `docs/` | ✅ | 코드와 문서 |
| `data/raw/**` | ❌ | 원본 공공데이터(약 143MB). 재배포 조건 미확인 |
| `data/marts` 중 앱 런타임 mart | ✅ | 배포 앱이 읽는 경량 산출물 15개(합계 약 0.9MB). 아래 참고 |
| `data/staging/**`, `data/interim/**` | ❌ | 중간 산출물. 스크립트로 재생성 |
| `data/marts` 중 학습·대용량 mart | ❌ | `congestion_training_mart`(706,678행), 승하차 mart(15,957,680행) 등. 앱이 읽지 않음 |
| `models/**` | ❌ | 재학습 가능(약 33MB). 채택된 것은 baseline lookup 이다 |
| `reports/route/route_eval_cases*.csv` | ❌ | 행 수가 많은 원시 결과. 요약 CSV 와 리포트는 포함 |

### 저장소에 포함한 런타임 mart

배포 앱이 실행 중에 읽는 파일만 포함합니다. 파이프라인을 돌리지 않아도 앱이 동작합니다.

```
route_edge_mart              transfer_edge_mart           congestion_edge_lookup
congestion_station_profile   transfer_tip_mart            event_did_mart
event_spike_mart             headway_station_30min        headway_line_30min
route_evaluation_mart_{0830,1800,20250927_1800}
route_evaluation_summary_{0830,1800,20250927_1800}
```

`models/` 는 포함하지 않습니다. 사전 등록한 판정에 따라 baseline 을 서비스에 쓰므로
앱 런타임에 모델 파일이 필요 없습니다.

`data/master` 를 포함한 것이 이 저장소의 핵심 판단입니다. 마스터는 "데이터"가 아니라
**프로젝트가 무엇을 대상으로 하는지에 대한 정의**이므로 코드와 함께 버전 관리해야 합니다.

## 3. 배치 위치

```
data/raw/
├── ridership_monthly/       홈페이지 *역별*시간대별*이용인원*.xlsx      (48)
├── congestion_quarterly/    서울교통공사_지하철혼잡도정보_*.csv|xlsx   (11)
├── transfer_volume/         서울교통공사_환승역환승인원정보_*.csv|xlsx (9)
├── transfer_detail/         서울교통공사_수도권 도시철도 환승 데이터.csv
├── route_distance_time/     *역간거리*.csv                             (3)
└── train_operation/         *열차운행현황*, *승객유형별*
```

파일명을 바꾸지 않았다면 각 스크립트가 패턴으로 자동 인식합니다.
Windows 사용자는 `setup_and_run.ps1 -RawDir "<원본 폴더>"` 로 분류·실행을 한 번에 할 수 있습니다.

## 4. 원본에서 실제로 발견한 문제

파이프라인이 대응하는 실제 결함입니다. 문서로만 적은 것이 아니라 코드가 처리합니다.

| 문제 | 대응 |
|---|---|
| 혼잡도 원본 스키마가 **3종**으로 갈라짐 (컬럼 구성·시트 분리·시각 표기) | `03` 이 자동 감지 |
| 2022 파일만 요일유형이 `공휴일` (이후 `일요일`) | `is_holiday_labeled` 로 구분 보존 |
| `20241231.csv` 요일값에 좌우 공백 | strip |
| `20250331.xlsx` 에 빈 `Sheet1` 혼입 | 스킵 |
| **5호선 둔촌동·올림픽공원이 2호선으로 잘못 기재된 156행** | 역번호 체계로 재판정, `is_line_corrected` 기록 |
| 두 마트의 `station_uid` 규칙 불일치로 조인 매칭률 0% | `(line_id, station_code)` 조인으로 전환 |
| 역간거리 파일이 역 목록이 아니라 **호선별 단일 순회 경로** | `SEQUENCE_BREAKS` 로 지선 시작점 명시 |
| 6호선 응암순환이 **단방향** | `is_bidirectional=0`, 비대칭 엣지 |
| 역명 개명 6건(신천→잠실새내, 당고개→불암산 등) | `station_alias_master` |
