### 핵심 아키텍처

- 사용자 입력은 **역 단위**, 내부 그래프·혼잡도는 **호선별 station_uid** 단위.
  환승역에서 첫 승차 노선은 알고리즘이 후보로 비교하며, **최초 승차는 환승으로 세지 않습니다**
  (가상 노드 `V_ORIGIN_*` / `V_DEST_*`, origin_access·destination_exit 엣지).
  이 가상 노드는 `evaluate()` 에 들어가기 전에 제거됩니다.
- **비용 계산은 `RouteScorer.evaluate()` 한 곳에만 있습니다.**
  `10_evaluate_routes.py` 의 `evaluate_path()` 는 `rs.evaluate()` 결과에 10 전용 필드만
  덧붙입니다. 과거에 이 둘이 따로 계산해 앱과 리포트가 갈라진 적이 있으니(§2)
  **비용 계산을 새로 복제하지 마세요.**
- 노선도 좌표의 source of truth 는
  `data/master/yeoyuro_seoul_vector_map_coordinate_workbook.xlsx` (5120×2880).
  **자동 graph layout(spring/kamada_kawai) 사용 금지.**
  좌표를 고칠 때는 이 워크북을 직접 열어 수정하고
  `python scripts\14_import_map_workbook.py --root . --preview` 로 재생성합니다.
  Downloads 를 경유하지 않습니다.
- 방면 표기는 **경로상 다음 역** 기준입니다(예: "아차산 방면").
  종점 기준은 지선·순환에서 예외가 많아 폐기했습니다(`bound_label` 에 참고용으로만 보관).

### 그래프 모델링 — 과거에 깨진 지점들

| 문제 | 대응 |
|---|---|
| 분기역 단일 노드 → 지선 승객이 통과 | 성수·신도림·강동 본선/지선 노드 분리 |
| 응암순환 `구산 → 응암 → 역촌` 환승 0회 | `6_응암@eungam_loop` 분리 + 재승차 환승 엣지 |
| `구산 → 응암 → 새절 → 응암 → 역촌` U턴이 재승차 우회 | **역 재방문 금지** 제약 |
| 환승 호차/문이 진행 방향 무시 | 경로 앞뒤 역으로 방면 매칭 |
| **직결 분기를 셔틀 지선과 동일 취급** | 경로 앞뒤 노드로 통과 판정(아래) |

**U턴은 배차가 긴 낮 시간대에만 나타나 08:30 검증에서 놓쳤습니다.**
그래서 회귀 테스트는 5개 시간대(08:30/11:30/13:30/19:00/22:00)로 돌립니다.

### 5호선 강동 직결 분기

`열차운행현황` 구간 표기가 판별 근거입니다.

```
5호선 : 방화~하남검단산/마천          영업거리 59.8      시격 2.5/6.5   운행횟수 428
2호선 : 성수~성수[성수지선/신정지선]     영업거리 48.8[5.4/6.0]           운행횟수 528[226/220]
```

2호선 지선은 대괄호로 분리돼 **별도 시격·운행횟수**를 갖는 셔틀이지만,
5호선은 마천지선을 포함해 **단일 계통**입니다. 방화에서 온 열차가 강동에서 갈라져
그대로 직결 운행합니다.

강동의 세 가지 이동은 엣지 하나로 구분되지 않습니다.

| 이동 | 판정 |
|---|---|
| 천호(본선) ↔ 길동(하남) | 직통 |
| 천호(본선) ↔ 둔촌동(마천) | **직통** (환승 아님) |
| 길동(하남) ↔ 둔촌동(마천) | 환승 |

그래서 `evaluate()` 와 `describe_path()` 가 **경로의 앞뒤 노드**를 보고 판정합니다
(`is_through_pass`, `THROUGH_JUNCTIONS`). 통과일 때는 승차 구간을 끊지 않으므로
분기역이 중간 정차역으로 계산됩니다.
**근본 해결은 계통 분리이며 v2 후보입니다(§8).**

### 사전 등록한 모델 판정 (뒤집지 말 것)

> LightGBM 이 `역×방향×요일×시간대 평균` baseline 을 valid 에서 이기지 못하면
> 모델을 폐기하고 baseline 을 서비스에 사용한다. → **판정: baseline 채택**

Skill Score: Regime A −0.464 / Regime B −0.012.
모델(Model-2, 역 식별자 제외)은 **미관측 역 보간용**으로만 유지합니다.

### 중간역 정차시간

원본 `역간거리 및 소요시간` 의 소요시간은 **순수 주행시간**입니다.
`열차운행현황` 의 공표 소요시간·표정속도와 교차검증해 확인했습니다.

| 호선 | 역간 합계 | 공표 소요 | 중간역당 |
|---|---|---|---|
| 1 | 14.0분 | 18.0분 | **30.0초** |
| 3 | 51.5분 | 67.5분 | **30.0초** |
| 6 | 55.5분 | 75.0분 | 30.8초 |
| 7 | 69.0분 | 87.0분 | 27.0초 |

→ `DEFAULT_DWELL_TIME_MIN = 0.5` (scripts/09).
**이 값은 κ=0.5, C0=80 같은 "초기값"과 성격이 다릅니다.** 공표 데이터에서 유도된 값입니다.

계산 규칙: 연속한 ride 엣지 묶음마다 중간 정차역 수 = `max(k-1, 0)`.
출발역·도착역·환승 하차역·환승 승차역은 정의상 제외됩니다.
`actual` 과 `perceived` 에 **각각 1회, 혼잡도 보정 없이** 더합니다.

**엣지 가중치에 미리 섞지 마세요.** 같은 엣지도 경로에 따라 중간역일 수도 종점일 수도 있습니다.

## 2. 배포 후 발견한 것 — 같은 실수를 반복하지 않기 위해

v1 배포 뒤 직접 앱을 쓰다가 두 건을 찾았습니다.

**① 강동 직결 분기** — 광나루→오금이 강동 환승 1회로 안내됐습니다.
성수·신도림과 같은 방식으로 노드를 분리한 게 과했습니다.

**② 평가 계산 중복** — `10_evaluate_routes.py` 가 `RouteScorer.evaluate()` 를 쓰지 않고
`edge_meta` 로 비용을 따로 계산하고 있었습니다. 그래서 정차시간과 강동 통과 규칙이
앱에는 반영됐지만 평가 리포트에는 도달하지 못했습니다.

```
방화 -> 마천 (weekday 18:00)
  앱   : 환승 0회 / 88.70분 / 정차 22.0분
  마트 : 환승 1회 / 69.25분
```

**②의 여파가 큽니다.** 정차시간을 넣은 직후 재평가에서 08:30 3/13, 18:00 0/13 이
그대로 나와 "핵심 결론 유지"로 기록했는데, 그건 결론이 견고해서가 아니라
**변경이 검증 경로에 도달하지 못했기 때문**이었습니다. 통합 후 실제로는
18:00 이 0/13 → 2/13 으로 바뀌었습니다. 경위는
`docs/dwell_time_adjustment_report.md` §6 에 정정 기록으로 남겼습니다.

> **수치가 변하지 않았을 때 "결론이 견고하다" 로 해석하기 전에,
> 변경된 계산이 실제로 검증 경로에 반영되었는지부터 확인해 주세요.**

## 4. 테스트 구성 (116건)

| 파일 | 건수 | 검증 대상 |
|---|---|---|
| `test_station_routing.py` | 41 | 경로 탐색 regression (지선·순환·U턴·재방문 금지) |
| `test_transfer_direction.py` | 27 | 환승 방면 표기, 자기역명 이상값, substring 오탐 방지 |
| `test_dwell_time.py` | 18 | 중간역 정차시간 개수·합산·이중보정 방지 |
| `test_through_junction.py` | 17 | 강동 직결 분기 통과, 하남↔마천 환승 유지 |
| `test_timeline_consistency.py` | 13 | 화면 표시값과 카드 총계의 일치 |

**각 파일이 왜 있는지 기억해 주세요.**

`test_timeline_consistency.py` — dwell 을 `evaluate()` 에만 반영하고 `describe_path()` 의
segment `minutes` 를 빠뜨려 총계 38분 / segment 29분 으로 어긋난 적이 있습니다.
고치는 과정에서 `sys.modules` 로 scorer 모듈을 찾았는데, `load_scorer_class()` 는
`module_from_spec` + `exec_module` 로 모듈을 만들고 **`sys.modules` 에 등록하지 않아**
조회가 `None` 을 반환하고 상수가 조용히 0.0 으로 떨어졌습니다.
현재는 `station_routing._dwell_min()` 이 클래스의 `__globals__` 를 직접 읽습니다.

`test_through_junction.py` — **미적용과 과잉적용을 각각 다른 테스트가 검출**합니다.
통과 예외를 없애면 `trunk_to_macheon_is_not_a_transfer` 가, 무조건 통과로 바꾸면
`branch_to_branch_still_transfers` 가 실패합니다. 한쪽만 검증했다면 과잉 수정을 놓쳤을 겁니다.

**`evaluate()` 반환값만 검사하는 테스트로는 위 결함들이 잡히지 않았습니다.**
표시값과 양방향을 검증하는 테스트를 유지해 주세요.

### 기각한 기법과 이유 (다시 제안하지 말 것)

| 후보 | 기각 사유 |
|---|---|
| LSTM / Transformer / GNN | 혼잡도 스냅샷이 11개. 격자당 관측치 11개에 딥러닝은 과적합 |
| NDCG / MAP | 정답 선호도 라벨(사용자 피드백)이 없음 |
| MASE | 시계열 naive forecast 를 분모로 쓰는 지표라 격자 회귀에 정의 불일치 → Skill Score |
| MLflow | 학습이 사실상 1회 |
| Great Expectations | pandera 로 충분 |
| A/B 테스트 | 사용자 없음 |
| Hugging Face Spaces | Streamlit SDK 생성 불가, 컴퓨트 Space 는 PRO 유료 |

### 화면 구성

`쾌적 경로 찾기` / `시간대별 혼잡 조회` / `빠른 환승 안내` / `이벤트 혼잡 경보` /
`프로젝트 소개 및 검증 리포트` 5개 메뉴입니다.

경로 카드 하단에 **구간별 기대 혼잡도 그래프**가 있습니다.

- 혼잡도는 역이 아니라 **구간**의 값이므로, 구간 중간역은 떠나는 엣지 값을,
  마지막 역은 도착하는 엣지 값을 갖습니다. 도착역까지 선이 이어지고
  환승역에서는 두 호선 값이 각각 표시됩니다(4호선 사당 = 이수→사당, 2호선 사당 = 사당→방배)
- 승차 구간별로 trace 를 나눠 환승 지점에 불연속을 만듭니다.
  직결 분기 통과는 같은 열차이므로 구간을 끊지 않습니다
- 시간대 대안이 있을 때만 추천 시각 곡선을 겹칩니다(경로 동일성 확인 후)
- 모바일 스크롤을 막지 않도록 `fixedrange=True`, `dragmode=False`, `scrollZoom=False`

대안 경로 선정은 **최속 경로와 추천 경로를 모두 배제**합니다. calm 모드처럼 추천이
최속과 다를 때 같은 경로가 대안으로 다시 제시되던 문제를 v1 후반에 고쳤습니다.

노선도(Plotly)는 `dragmode="pan"`, `fixedrange=False` 라 **모바일에서 페이지 스크롤을
가로챕니다.** 미해결 UX 이슈입니다(§7).

## 7. v1 의 알려진 한계 (v2 후보)

1. **출발 시각의 time_bin 을 경로 전체에 고정** — 시간 전진 미반영.
   정차시간을 반영해 총 소요시간이 늘어난 만큼 이 한계의 영향도 커졌습니다.
2. **환승 대기시간이 30분 bin 평균** — 특정 시각의 실제 다음 열차가 아님.
   균등 도착 가정(기댓값 = 배차/2), 최초 승차 전 대기는 미반영.
3. **강동 직결 분기는 예외 처리** — 근본 해결은 계통 분리입니다. 또한 **탐색 단계의
   비용에는 통과 예외가 반영되지 않습니다**(Yen's K-shortest 는 정적 가중치를 쓰므로).
   `evaluate()` 가 최종 점수를 바로잡지만 후보 집합 자체는 페널티가 붙은 채로 만들어집니다.
4. **고혼잡 구간 오차** — ~30% 구간 MAE 1.474 vs 130%+ 구간 9.227.
   현재는 절대값 대신 상대 순위(p95 초과)로 우회.
5. **`label_high` 기준 불일치** — station holdout 역은 train 에 없어 전역 p95 로 대체.
   Regime B 분류 지표에 편향이 있음.
6. **Pareto front 는 K개 후보 안에서의 front** — Yen's K-shortest 집합에 한정.
7. **정차시간이 단일 상수** — 노선·역·시간대별 실제 정차시간은 다름.
8. **모바일 노선도 스크롤** — 지도가 터치를 가로채 페이지 스크롤이 막힙니다.
   확대·이동 토글(기본 끔)을 두는 방안을 검토했으나 아직 적용하지 않았습니다.
9. **미해결** — 혼잡도 산식(정원 대비 %인지), 스냅샷 날짜의 의미(관측 종료일/발행일),
   8호선 오차가 큰 원인(MAE 3.600, p95 오차 13.9).
10. **노선도 도심부 라벨 밀집** — 서울역·시청·충정로 주변.
11. **원본 데이터 이상값** — `docs/known_data_issues.md` 참고.
    강동 5→5 방면 표기는 UI sanitizer 로 방어 중이며,
    경로 기준 방면 유도 표시는 v1.1 과제로 남겨뒀습니다.

## 9. 작업 방식 요청

- 스크립트를 수정하면 **실제로 실행해서 출력값을 보여주세요.** 확인값과 대조하겠습니다.
- 파일을 여러 곳 고칠 때는 **한 번에 묶어 패치하지 말고** 단계별로 저장·검증해 주세요.
- **여러 곳을 고치는 패치는 PowerShell 인라인 대신 `.py` 스크립트 파일로 주세요.**
  v1 에서 PowerShell 붙여넣기로 여러 번 실패했습니다.
  - here-string(`@'`)은 줄 맨 앞에서 시작해야 하고, 배열 안에 들여쓰면 파싱 오류가 납니다
  - `&` 가 들어간 문자열은 인라인에서 막힙니다
  - 한 줄씩 실행하면 `return` 가드가 작동하지 않아, 중단돼야 할 쓰기가 진행됩니다
  - bash 의 `<<'EOF'` 는 PowerShell 에서 동작하지 않습니다
  - ps1 파일은 실행 정책(서명 없음)에 막힙니다. `.py` 가 가장 확실합니다
- 패치 스크립트에는 항상 다음을 넣어주세요.
  - 파일의 줄바꿈(CRLF/LF) **감지** 후 패턴에 맞추기. 파일마다 다릅니다
  - 치환 전 **매칭 건수 출력**, 1건이 아니면 중단
  - 백업 → 문법 검사 → 실패 시 자동 복원
  - 같은 문자열이 파일에 여러 번 나올 수 있으니 앞뒤 문맥을 넓히거나 줄 번호를 쓰세요
- 파일을 주실 때는 Downloads 에 남지 않도록 `Move-Item` 기준 명령으로 안내해 주세요.
- `data/master` 등 프로젝트가 생성한 실데이터를 덮어쓰지 마세요.
- 그래프·라우팅을 건드리면 반드시 `pytest tests/ -q` 로 **116개 통과**를 확인해 주세요.
- 새 기능을 추가하면 회귀 테스트도 함께 추가해 주세요.
  **테스트가 실제로 버그를 잡는지** 일시적으로 결함을 주입해 확인하는 것까지 포함합니다.
  가능하면 **양방향**(미적용·과잉적용)을 각각 다른 테스트가 잡도록 해주세요.
- 문서에 숫자를 적을 때는 다른 문서와 충돌하지 않는지 확인해 주세요.
