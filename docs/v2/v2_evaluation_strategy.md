# v2 평가 전략

> v2 의 결론이 **"결과를 보고 기준을 맞춘 것이 아님"**을 어떻게 보장했는지 정리한다.
> v1 의 평가 전략(모델 판정·Skill Score·불균형 지표)은 [`docs/evaluation_strategy.md`](../evaluation_strategy.md) 에 있다.
> 수치는 각 리포트에서 인용하며, 결론 요약은 [v2_results.md](v2_results.md) 에 있다.

## 1. 원칙

| 원칙 | 구현 |
|---|---|
| **판정 기준을 결과보다 먼저 고정한다** | 분석마다 사전 등록 문서를 먼저 커밋하고, 분석 스크립트가 그 커밋을 git 으로 확인한 뒤에만 실행된다. 리포트 첫 줄에 커밋 해시를 남긴다 |
| **기준을 바꾸면 기록한다** | 등록 문서는 고치지 않고 `decision_log.md` 에 새 ID 로 남긴다 (예: D-053 v2.6c 는 결과를 본 뒤 떠올린 검사라 별도 등록) |
| **반증 가능한 가설로 쓴다** | 가설마다 "이 값이면 기각" 조건을 미리 적는다. 반증된 가설도 그대로 보고한다 (v2.5 H4a·H4b 반증) |
| **하나의 점수로 뭉치지 않는다** | 노출 시간·최대 혼잡·구조적 비율·대안 기회를 따로 보고한다. 단일 스트레스 점수는 만들지 않는다 |
| **표본의 한계를 숫자 옆에 쓴다** | "무작위 역 쌍 기준", "과거 패턴 기반 기대값", "가정 시나리오"를 결과와 같은 문장에 둔다 |
| **수치는 데이터에서 다시 나와야 한다** | 핵심 수치를 커밋된 mart 에서 다시 계산하는 테스트를 CI 에서 돌린다 (D-082) |

## 5. 이 체계가 막지 못하는 것

- **혼잡 원자료의 한계**: 분기 스냅샷 평균이라 특정 날짜·이벤트 당일의 실제 혼잡은 검증할 수 없다. 이벤트 결과는 가정 시나리오다.
- **9호선 환승 보행시간**: 실측이 아닌 보정 proxy. 민감도로 결론 의존성만 확인했다.
- **사용자 행동**: "시간을 옮기면 피할 수 있다"는 한 사람이 옮길 때의 계산이며, 많은 사람이 함께 옮길 때의 재분배는 반영하지 않는다.
- **사전 등록의 범위**: v2.6c 처럼 결과를 본 뒤 떠올린 검사는 등록을 먼저 했더라도 탐색적 성격이 남는다. 문서에 그렇게 적는다.
