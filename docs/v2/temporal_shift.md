# Time Shift (출발 시각 조정)

v2.2 결론: **현재 기준(T0: ±90분, 노출 또는 최대혼잡 감소)으로는 혼잡한 이동의 100% 가 "시간 조정 가능"으로 나온다.**
지하철 피크가 30~60분으로 좁아서, ±90분이면 거의 항상 피크를 벗어나기 때문이다.
이대로면 Time 축이 변별력을 잃으므로, 주 기준(창 크기·감소 기준)은 v2.3 사전 등록에서 다시 정한다.
수치 출처: [`reports/v2/temporal_shift_report.md`](../../reports/v2/temporal_shift_report.md)
(Tier C 20쌍 + 무작위 150쌍 × 평일 기준 출발 6개 = 1,020건, 후보 6,362행).

## 1. 판정 규칙 (T0, D-015·D-016)

| 항목 | 값 |
|---|---|
| 후보 시각 | 기준 ±30 / 60 / 90분 (운행 창 밖 제외) |
| 감소 | exposure_100 ≥5분 감소 **또는** 최대 기대혼잡 ≥15%p 감소 |
| 비용 | 소요시간 증가 ≤5분 |
| 경로 | 같은 경로, 또는 그 시각 최속 경로가 edge Jaccard ≥0.8 |
| 제외 | 기준 이동이 Calm (노출 <3분이고 최대 <100%) 이면 판정 안 함 |
| Top 3 정렬 | 이동폭 작은 순 → 노출 감소 큰 순 → 같은 폭이면 늦게 (가중치 없음) |

구현: `yeoyuro_v2/temporal_shift.py`, 앱 '시간 분산' 페이지와 경로 페이지의 시간 대안 안내.

## 3. 창 크기·감소 기준 민감도 (Calm 제외 476건)

| 창 | 노출 또는 최대혼잡 (T0) | 노출 감소만 |
|---|---|---|
| ±30분 | 77.5% | 39.7% |
| ±60분 | 98.7% | 57.6% |
| ±90분 | 100.0% | 60.1% |

같은 데이터에서 Time 축 성공률이 39.7%~100% 로 움직인다. 이 선택이 v2 중심 가설의 Structural 비율을 사실상 결정하므로,
결과(Route × Time 교차)를 보기 전에 고정한다 (D-017).

해석 시 주의: "노출 감소만" 기준은 기준 노출이 5분 미만인 이동(최대혼잡 ≥100 이라 Calm 이 아닌 경우)에서 구조적으로 성공할 수 없다.
그 이동들이 "시간으로 못 피한다"로 분류되는 것은 혼잡 구조가 아니라 기준의 산물이다.

## 4. v1 대비 바뀐 점

- 창: ±120분 → ±90분 (+ 사전 등록에서 주 창 재결정). v1 추천의 70.8% 가 90분 밖이었다.
- 기준: 최대혼잡 최소 bin 하나 → 규칙 통과 후보 Top 3, 노출 감소와 소요 변화를 함께 표시.
- 계산: 후보 시각에서도 구간 진입 시각을 누적 (v2.0 엔진).

## 5. 한계

- 균등 무작위 OD, 평일 6개 기준 시각. 수요 가중이 아니다.
- 혼잡은 외생 고정. 많은 사람이 시간을 옮기면 피크가 이동한다 (기획서 R1).
- "늦게 출발"이 도착 시각 제약(출근 시각)과 충돌하는지는 데이터로 알 수 없다. UI 문구는 제안이며 강요하지 않는다.
