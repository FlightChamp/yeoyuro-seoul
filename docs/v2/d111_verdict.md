# D-111 판정 기록 — 광역철도 확장 켬 + 3-B 켬 기본 탐색을 V4 로 (D-111b)

- 상태: **판정** (2026-11-27). [사전 등록](preregistration_d111.md) 3절 G0~G5 와 [D-111c G5 방법](d111_g5_method.md)으로 판정한다. 두 문서와 결과 보고서는 고치지 않는다.
- 이 문서는 판정 패치가 **G5 가 통과한 경우에만** 커밋한다. G5 가 보류이면 기본값은 v0 그대로이고, 이 문서는 커밋되지 않는다.

## 1. 판정

**통과 — `korail_app.DEFAULT_CAND = "v4"`.** 광역철도 확장을 켜고 3-B 정차표가 있을 때, 앱 계산기는 D-110b 에서 채택한 V4 로 후보를 찾는다.
- V4 = 대표 대기 합집합 + GJ·GC 유사 후보 묶기, 원시 후보 상한 40, k=10 그대로.
- 3-B 끔 계산기(3-A 만), 광역 끔, 평가기, 정렬, 상태 문구는 그대로다.

## 2. 실행 순서 (사실대로)

1. 사전 등록 c15f3af — 결과 전.
2. D-111a 구현 101bb52 — 기본값은 v0 그대로.
3. 사용자 PC 정식 실행: `53 --cand v4 --tag d111` → `55`. 결과를 커밋한 것은 보고서 4개뿐이다.
4. 결과를 본 뒤 G5 를 재기 전에, 49·51 의 옛 기준이 D-103·D-106 뒤로 v0 에서도 맞지 않는 것을 확인했다(샌드박스). 그래서 **D-111c 사후 규칙**으로 G5 를 v0 ↔ v4 비교로 정했다(사용자 결정). 규칙과 도구 56 은 G5 측정 전에 커밋했다.
5. 첫 판정 묶음 실행은 56 의 W2 작업자 풀에서 Windows spawn 피클 오류로 멈췄다. 보고서는 없었고 G5 값은 나오지 않았다. **D-111d**(도구 수정, 측정 전)로 고친 뒤 처음부터 다시 쟀다.
6. 판정 묶음 안에서 순서대로 실행했다: D-111d 커밋 → 56 실행 → G5 결과 커밋(보고서만) → 이 판정 커밋(기본값 v4·테스트·문서, pytest 통과 뒤).

## 3. 결과 변화 (보고만, 기준 없음)

- **확정 추천 바뀜**: 64/1,560 (4.1%). 상태 이동은 효과 없음 → 확정 25, 결과 없음 → 확정 4, 결과 없음 → 효과 없음 2, 참고 → 확정 1. 나빠진 방향의 이동은 없다.
- **실제 시간**: 두 쪽 모두 확정 추천이 있는 57건 중 줄어든 건 51, 늘어난 건 0이다. 중앙 −2.4분, 최대 −7.3분 (김포공항→서울역 토·일 14:00).
- **체감 시간**: 늘어난 건 2다. 정렬이 실제 시간 우선이므로 규칙대로다.
- **3-B 를 지나지 않는 확정 추천도 바뀜**: 바뀐 64건 중 44건이다. 대기를 넣은 후보 탐색이 1~9호선 경로(예: 김포공항→서울역)도 더 빠른 것을 찾았다.
