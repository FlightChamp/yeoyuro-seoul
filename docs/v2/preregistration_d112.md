## 1. 실행 모드와 fail-closed

| 모드 | 정하는 방법 | 3-B 자료 출처 |
|---|---|---|
| **로컬 개발** | 명시적으로 켤 때만: git 이 무시하는 표시 파일 또는 환경 변수 (이름은 D-112a 에서 정함) | 지금처럼 로컬 정차표 파일 — 전체 정밀 엔진 |
| **공개** | 그 밖의 모든 경우 (기본값) | 정책을 통과한 노선만 비공개 저장소에서 받음 |

- **공개 모드는 로컬 3-B 파일을 절대 읽지 않는다.** 파일이 우연히 있어도 읽지 않는다. Secrets 가 없거나 내려받기가 실패해도 로컬 파일로 넘어가지 않는다.
- 평가·검증 스크립트(53~56)는 개발 도구라서 지금처럼 로컬 파일을 직접 쓴다. 모드 판정은 앱과 앱 계산기 층에서만 한다.
- 공개 모드에서 노선 하나가 켜지려면 **아래 여섯 가지를 모두** 만족해야 한다. 하나라도 어긋나면 그 노선만 끄고, 나머지는 그대로 동작한다.

| # | 조건 | 어디서 확인 |
|---|---|---|
| C1 | 명시적인 공개 허용 결정 | 정책 파일 `status = "허용"` + 결정 D 번호 |
| C2 | 그 노선의 이용허락 근거 | 정책 파일 근거 항목 (D-107 후속 또는 공항철도 회신 기록) |
| C3 | 활성화 설정 | 정책 파일 `enabled = true` |
| C4 | 접근 권한 | 그 운영사 토큰이 Secrets 에 있고 인증에 성공 |
| C5 | 고정 해시 일치 | 받은 파일의 SHA-256 = 정책 파일에 적어 둔 값 |
| C6 | 스키마·데이터 검사 | 4절 검사 전부 통과 |

- 정책 파일은 공개 저장소에 둔다. 노선을 켜려면 그 파일을 커밋해야 하므로 언제 누가 켰는지 기록이 남는다. D-112a 에서는 **모든 노선을 `enabled = false`, `status = "보류"`** 로 둔다.

## 2. 꾸러미와 보관

| 운영사 | 노선 | 꾸러미 | 비공개 저장소 (예) | 토큰 |
|---|---|---|---|---|
| 코레일 | GJ·GC·SB | 정차표 parquet + manifest | `yeoyuro-data-korail` | 이 저장소만 읽는 최소 권한 |
| 공항철도 | AR | 정차표 parquet + manifest | `yeoyuro-data-arex` | 이 저장소만 읽는 최소 권한 |

- 꾸러미는 로컬 정차표에서 분리 스크립트로 만든다. 결과물은 git 이 무시하는 폴더에 쓴다.
- manifest 에는 다음을 적는다: 스키마 판, 운영사, 노선별 행 수·열차 수, 시각표 기준일, SHA-256, 원본 정차표 해시.
- **한 꾸러미에 다른 운영사 노선이 섞이면 꾸러미 전체를 쓰지 않는다.**
- 운영사 단위로 요청한다. 그 운영사의 노선이 하나도 켜지지 않았으면 **네트워크 요청을 보내지 않는다.** 꾸러미 안의 노선 중 일부만 켜졌으면 받은 뒤 켜진 노선 행만 남긴다.
- 받은 자료는 메모리 또는 임시 폴더에만 둔다. 저장소 폴더에는 쓰지 않는다.
- 앱은 비공개 파일을 직접 내려받는 링크를 제공하지 않는다.
- **그렇다고 정보를 다시 짜 맞출 수 없는 것은 아니다.** 서비스 화면에는 결과로 열차번호와 시각이 나온다. 그래서 질의를 반복하면 시각표 일부를 다시 짜 맞출 수 있다. 비공개 보관은 파일 재배포를 막을 뿐이다. 그래서 공개 활성화에는 C1·C2 (이용허락 근거)가 따로 필요하다.

## 3. 접근 제어와 노출 방지

- **토큰**
  - 저장소별로 따로 쓰는 읽기 전용 토큰이다 (fine-grained, 대상 저장소 하나, Contents 읽기).
  - Streamlit Secrets 에만 둔다. 저장소, 로그, 화면에는 두지 않는다.
- **요청**
  - HTTPS, 정해진 호스트만 쓴다 (GitHub API).
  - 토큰은 헤더에만 넣고 URL 에는 넣지 않는다.
  - 연결·전체 시간 제한과 파일 크기 상한을 둔다 (값은 D-112a 에서 정함. 지금 정차표 전체는 약 120KB).
- **순서**
  - 받기 → 크기 확인 → SHA-256 확인 → 그다음 파싱 → 4절 검사.
  - 해시가 맞지 않으면 파싱하지 않는다.
- **실패 기록**
  - 일반 코드만 남긴다: `auth`·`network`·`timeout`·`size`·`hash`·`schema`·`policy`.
  - 예외 원문, 응답 본문, 토큰, 정차표 행은 로그·예외 메시지·화면에 넣지 않는다.
- **화면**
  - 실패하면 지금 문구 수준의 안내만 보여 준다 (예: "확장 노선 자료를 불러오지 못해 코레일 1호선만 계산합니다").
  - 앱은 멈추지 않는다.

## 5. 노선 부분 집합의 그래프 일관성

켜진 노선 집합 E 에 맞춰 아래 항목이 모두 같은 E 를 따라야 한다. **꺼진 노선의 열차·주행 간선·환승 간선은 어떤 경로에도 들어가지 않는다.**

| 항목 | 규칙 |
|---|---|
| 정차표 | group ∈ E 인 행만 |
| GJC 묶음 | E 에 있는 GJ·GC 열차로만 만든다 |
| 역 목록·검색 가능 역 | 1~9호선 + 3-A + E 의 역. 꺼진 노선에만 있는 역은 검색 목록에 없다 |
| 주행 간선 | E 의 열차가 지나는 간선만 |
| 환승 간선 | 양쪽 노선이 모두 켜져 있을 때만 (1~9호선·3-A 는 늘 켜져 있음). 김포공항 방향별 보행은 AR 이 켜졌을 때만 |
| 노선도 | E 는 노선 색 실선, 나머지 3-B 는 지금처럼 회색 점선 |
| 후보 탐색·열차 연결 검증 | 같은 E 의 그래프와 열차 시각표만 쓴다 |
| 공항철도 | AR 이 켜져도 지금 정책 그대로 '참고 경로'로만 쓴다 (확정 추천 안 함, D-105) |

**의존성 정책 (미리 고정)**
- **GC 는 GJ 에 의존한다.** GC 열차는 청량리·회기·중랑에서 `GJ_` 노드와 `GJC` 간선을 지나기 때문이다. 그래서 GJ 없이 GC 를 켜면 꺼진 노선의 노드가 그래프에 남는다.
- 정책 검사기는 GJ 없이 GC 만 켜진 정책을 **거부하고 GC 를 끈다.**
- D-112a 에서 GC 만 켰을 때의 동작을 시험해 그 결과를 보고한다. 안전하게 지원할 수 있더라도 그것을 허용하려면 새 D 번호가 필요하다.

**검증할 조합 (D-112a)**

| 조합 | 기대 |
|---|---|
| 전부 끔 | 지금 공개 앱과 같음 (1~9호선 + 3-A), 3-B 요청 0 |
| GJ 만 | 오류 0, 경로·역·간선 ⊆ 1~9 + 3-A + GJ |
| SB 만 | 같은 기준 (SB) |
| AR 만 | 같은 기준 (AR, 참고 경로만) |
| 코레일 전체 (GJ·GC·SB) | 같은 기준, 공항철도 요청 0 |
| 전부 켬 | 로컬 개발 모드와 같은 결과 (고정 표본에서 확정 추천·참고 경로·상태·기대 소요 일치) |
| GC 만 | 정책 검사기가 거부 → GC 꺼짐. 실제 그래프 동작은 보고만 |

## 6. 기존 서비스 보존 (D-112a 통과 기준)

1. 기존 테스트 520개가 그대로 통과한다 (새 테스트는 더해짐).
2. 로컬 개발 모드의 전체 정밀 엔진 결과가 유지된다. 대표 표본에서 지금 코드와 확정 추천·참고 경로·상태·기대 소요가 같아야 한다.
3. 공개 모드에서 정책이 전부 false 이면 지금 1~9호선·3-A 기능이 그대로다. 화면 지문은 D-111c 방식으로 비교한다.
4. V4 기본 탐색(D-111b)과 D-111 판정 결과를 보존한다. 판정 문서와 보고서는 고치지 않는다.
5. 공항철도 참고 경로 정책을 보존한다.
6. 켜지지 않은 노선의 역과 경로가 나오지 않는다.
7. 내려받기가 실패해도 앱이 멈추지 않고, 허용된 노선으로만 계산한다.
8. 보안 검사
   - 가짜 토큰 문자열이 로그·예외·화면 출력에 없다.
   - 정차표 행이 오류 메시지에 없다.
   - 꺼진 운영사로 요청하지 않는다 (모의 응답으로 확인).
   - 해시나 스키마가 틀리면 그 노선이 꺼진다.
   - 공개 모드에서 로컬 3-B 파일을 열지 않는다.
   - 정차표와 꾸러미가 git 에 추적되지 않는다.

구조 검증에는 **가짜 토큰, 합성 정차표, 모의 내려받기 응답만** 쓴다.

## 7. 권한 확인 전에 하지 않는 것

- 비공개 원격 저장소에 실제 데이터 업로드
- 실제 접근 토큰 발급과 Streamlit Secrets 설정
- 공개 앱의 3-B 활성화 (정책 파일 `enabled = true` 커밋)
- 원본·파생 정차표의 공개 커밋

승인을 받은 뒤에는 승인 범위 안의 노선만 켠다. 순서는 이렇다. 노선별로 새 D 번호를 붙인다.
1. 저장소 만들기, 토큰 발급, 업로드, Secrets 설정
2. 정책 파일 커밋
3. Cloud 에서 3-B 켬 검색 시간·메모리 확인 (V4 계산기의 Cloud 성능은 아직 잰 적 없음)
