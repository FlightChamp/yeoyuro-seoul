# D-109 사전 등록 (1단계) — 광역철도 확장 카드의 상태 문구·기준 표시 정리

- 상태: **사전 등록** (2026-11-28, 구현 전). 이 문서는 커밋한 뒤 고치지 않는다. 바꿀 일이 생기면 새 D 번호(사후·후속)를 붙인다.
- 사용자 결정 (2026-11-28): 다음 주 교수님 면담 시연을 앞두고, 원래 D-109 범위(상태 문구 + 공개 앱 통합) 가운데 **지금 정밀 엔진에 해당하는 문구 정리**를 먼저 한다.
  - 공항철도 집계 모델(D-108)에 딸린 상태("통계 기반 예상 경로")와 공개 앱 3-B 통합은 **2단계**로 남긴다. 2단계는 D-107 이용허락과 공항철도 회신 뒤 새 D 번호로 한다.
  - 원래 설계: 프로젝트 문서 「3B 공항철도 집계 설계 검토」 6절.
- **계산은 바꾸지 않는다.** 경로 탐색, 평가, 열차 연결 검증, 확정 추천 선택, 공항철도 참고 경로 정책(D-105)은 그대로다. 화면 문구와 배치만 바꾼다.

## 1. 바꾸는 것 (구현 D-109a)

| # | 바뀐 뒤 | 대상 |
|---|---|---|
| C1 | 확정 추천 상태 표시: "**✅ 계획 시각표로 전체 연결 확인** · 환승 n회". 내부 상태 값 `CONNECT_OK = "연결 확인"` 은 그대로 두고, 화면에 보이는 이름만 바꾼다 (`CONNECT_LABEL`) | 확장 카드 |
| C2 | 노선별 시각표 기준일 줄을 **항상** 보여 준다. 쓰인 노선만 적는다. 예: "시각표 기준일: 1~9호선·코레일 1호선 2026-09-01 · 수인분당선 2026-08-22" | 확장 카드 (확정 추천·참고 경로) |
| C3 | `BASIS_STATIC` 에서 날짜를 뺀다: "계획 시각표 기준이며 실시간 지연·운행 변경은 반영하지 않습니다." (날짜는 C2 줄이 맡는다) | 확장 카드 |
| C4 | 사용자 문구에서 내부 기호 R4·E 를 뺀다. 뜻은 그대로 쓴다. 예: "기대 소요 = 첫 열차를 기다리는 시간은 빼고, 갈아타는 역에서는 그 시각 30분 평균 대기를 더한 값입니다." | `BASIS_EXPECTED`, 열차 펼침의 첫 대기 문구 |
| C5 | 계산 기준 두 줄(`BASIS_EXPECTED`·`BASIS_TIMETABLE`)은 "계산 기준" 펼침 안으로 옮긴다. `BASIS_STATIC` 한 줄과 C2 기준일 줄은 밖에 둔다 | 확장 카드 |
| C6 | 첫 열차 대기가 있으면 지표 바로 아래에 한 줄: "시각표 확인 도착은 첫 열차까지 기다림 n분을 포함합니다." | 확장 카드 |
| C7 | 뺀 후보 문구: "계획 시각표상 탈 수 없어 확정 추천에서 뺀 경로: …" (사유 이름은 그대로) | 확장 카드 |

**바꾸지 않는 것**
- 1~9호선 기본 카드
- 혼잡 진단 카드
- 노선도
- 끔 화면 전체
- 공항철도 참고 경로 제목(`REFERENCE_TITLE`)·설명(`AR_REFERENCE`) 문구와 순서 — 53 B13 앱 검사(D-105)가 쓴다
- 확정 추천 블록이 `**✅` 로 시작하는 형식 — 53 B13 이 이것으로 블록을 찾는다
- 혼잡도 미확인 배지·쾌적 판정 안 함 문구 (`BADGE_UNKNOWN`·`NO_COMFORT`)
- 안내 문구(`K3B_MISSING`·`K3B_PARTIAL`·`NONE_FOUND`·`NO_BENEFIT*`·공휴일·토요일 문구)

## 2. 통과 기준 (D-109a)

| # | 기준 | 확인 방법 |
|---|---|---|
| V1 | 계산 불변 | 바뀐 코드는 상수와 앱의 `render_extension` 뿐이다 (diff 범위 검사). `plan()` 결과는 손대지 않는다. 화면 지문(D-111c 방식, 끔 17 + 켬 3 사례)에서 **끔 화면 17사례는 모든 항목이 같고**, 켬 3사례는 지표(metric)·노선도·역 목록이 같아야 한다. 켬 화면의 문구·markdown 차이는 C1~C7 로 설명되는 것만 허용 |
| V2 | 기존 검사 | pytest 전체 통과. 49 W6·W7 문구 플래그와 53 B13 앱 검사는 상수 이름으로 비교하므로 그대로 통과해야 한다 |
| V3 | 내부 기호 없음 | 확장 카드 사용자 문구(캡션·markdown·지표 도움말)에 "R4"·"(E)" 가 없다 (테스트) |
| V4 | 기준일 | 쓰인 노선의 기준일만, 정확한 값으로 나온다. 1~9호선·코레일 1호선 2026-09-01, 경의중앙·경춘 2026-09-01, 수인분당 2026-08-22, 공항철도 2025-12-29 (`korail_3b.VALID_FROM`). 3-B 를 안 쓰는 경로에는 3-B 날짜가 없다 (테스트) |
| V5 | 공개 모드 | D-112 정책이 전부 꺼진 공개 모드에서도 예외 없이 같은 문구 규칙 (테스트) |

- 문구를 직접 비교하던 기존 테스트가 C1~C7 때문에 바뀌어야 하면, 구현 기록(D-109a)에 테스트 이름과 이유를 하나씩 적는다. 문구가 아닌 기대값(경로·시간·상태 값)을 바꾸는 테스트 수정은 하지 않는다.

## 3. 범위와 일정

- D-109a 하나로 끝낸다. 상수(`korail_app.py`), 앱(`render_extension`), 테스트, 결정 기록만 바꾼다.
- 공개 앱에는 push 뒤 그대로 반영된다. D-113 안전장치가 있어 다시 시작하지 않아도 새 모듈을 읽는 것이 기대값이다. 실제로 그렇게 되는지는 미확인이라, push 뒤 v2-demo 에서 확인한다.
- 면담 전날까지 push 를 끝내고, 당일에는 push 하지 않는다 (2026-11-28 Cloud 오류 교훈).
