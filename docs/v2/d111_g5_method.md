# D-111c — G5 앱 확인 방법 (사후 규칙)

- 상태: **사후 규칙**. D-111 결과(53 d111·55 비교)를 본 뒤이고, **G5 측정 전**에 커밋한다 (2026-11-27).
- [D-111 사전 등록](preregistration_d111.md)은 고치지 않는다. 이 문서는 그 3절 G5 의 "앱 확인 스크립트 49·51 통과"를 어떻게 잴지만 정한다.
- 사용자 결정 (2026-11-27): v0 ↔ v4 비교로 판정한다.

## 1. 왜 바꾸나

- 49(D-101)·51(D-104)의 화면 검사는 **구현 전 앱과 비교**하는 옛 기준이다. 그 뒤 D-103(심야 운행일)·D-106(끔 화면 노선도 회색 점선, 3-B 18역)이 화면을 일부러 바꿨다.
- 그래서 D-111을 적용하기 전인 지금 코드(v0)에서도 옛 기준이 맞지 않는다. 샌드박스 확인(2026-11-27, 101bb52):
  - 49 W1 구현 전 앱과 같음 0/14 (14사례 모두 노선도, 노량진→온수 2026-11-28 00:30 은 지표·문구도)
  - W3 켬 역 +36 (D-101 기준 +18)
  - W4 끔 점선 1 (D-101 기준 0)
- 51 H6 도 같은 이유로 맞지 않을 것으로 본다 (샌드박스 미확인).
- 이 상태로는 G5 가 D-111과 관계없이 미달이 된다. D-111 사전 등록을 쓸 때 이 점을 확인하지 않았다.

## 2. 방법 (`scripts/v2/56_check_d111_g5.py`)

같은 코드에서 기본 후보 탐색(`korail_app.DEFAULT_CAND`)을 v0 과 v4 로 각각 두고, 프로세스를 따로 띄워 49·51의 같은 검사를 돌린다.

| 묶음 | 무엇 | 기준 |
|---|---|---|
| S1 끔 화면 | 49 W1 14사례 + 51 공휴일 3사례의 지금 앱 화면 지문: 지표, 문구, 안내, 경고, 역 목록, 노선도(sha256), 예외 | v0 = v4 |
| S2 켬 화면 구조 | W3 역 목록·전환, W4 노선도, W6·W7 3사례의 문구 표시·기존 카드 = 끔·예외 | v0 = v4 (시간 값 제외) |
| S3 자정 사례 | W5 | v0 = v4 |
| S4 옛 기준 비교 결과 | 49 W1, 51 H6·H7 (구현 전 앱과 비교한 차이 목록) | v0 = v4. 옛 기준 충족 여부는 보고만 |
| S5 3-B 끔 계산기 | W2 412쌍 × 41시각, H9 412쌍 × 3 | 원래 절대 기준: 오류 0 · 확정 추천 연결 불가 0 |
| v4 절대 기준 | W3 목록 전환(중복 0·비움·목적지 유지·안내·예외 없음), W6·W7 기존 카드 = 끔·예외 없음 | 충족 |
| 보고 | W6·W7 켬 화면 전체 지문이 v0 과 다른 사례 | 기준 없음 (확정 추천이 바뀌면 생길 수 있음) |

- 실행 확인: 각 프로세스에서 앱 안에 실제로 만들어진 계산기의 (3-B 켬, 설정)을 기록한다. v4 실행에 3-B 켬 v4 계산기가 없거나, 3-B 끔 계산기가 v0 이 아니면 실행 오류로 멈춘다.
- 3-B 끔 계산기(W2·H9)는 설정과 무관하다(`cand_router_kw`, 테스트). 그래서 한 번만 돌리고, 원래 절대 기준으로 본다.
- pytest 는 판정 패치가 기본값 v4 상태로 따로 돌린다 (G5 의 나머지 절반).

## 3. 판정

- S1~S5 와 v4 절대 기준이 모두 맞고 pytest 가 통과하면 G5 통과다. 그러면 G0~G5 가 모두 통과이므로 같은 판정 패치에서 `DEFAULT_CAND = "v4"`로 바꾼다 (D-111b).
- S1~S4 에서 차이가 나거나 S5·절대 기준이 맞지 않으면 **보류**다. 기본값은 v0 으로 두고, 차이를 보고한 뒤 새 D 번호로 정한다.
- 산출: `reports/v2/d111_g5.{md,json}`. 결과 커밋은 따로 하고(보고서만), 판정 커밋은 그다음에 한다.
