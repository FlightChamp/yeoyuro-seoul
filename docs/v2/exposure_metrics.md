# 혼잡 노출 지표 (Exposure metrics)

v2.1 결론: **"최대 기대혼잡"과 "100% 이상 구간을 지나는 시간"은 서로 다른 경로를 고른다.**
혼잡 노출이 있는 OD×출발 1,559건 중 26.2% 에서 두 기준의 최선 경로가 달랐다.
그래서 v2 는 exposure_100 을 헤드라인으로, max 를 보조로 쓴다.
수치 출처: [`reports/v2/exposure_metrics_report.md`](../../reports/v2/exposure_metrics_report.md)
(Tier C 20쌍 + 무작위 150쌍 × 평일 출발 24개, 4,056건, 경로 23,172행).

## 1. 정의

```
exposure_X_min = Σ (차내 시간 조각의 길이)   단, 그 조각의 기대 혼잡도 ≥ X
```

- 차내 시간 = 주행 + 중간역 정차. 환승 도보·대기는 제외(승강장 혼잡 데이터 없음, D-005).
- 혼잡도는 구간 진입 시각의 bin 값(step 정책, D-002). bin 경계를 넘는 구간은 나눠서 센다.
- `exposure_X_min_p90`: 같은 계산을 스냅샷 p90(붐비는 날)으로 한 값.
- X = 80 / 100 / 130. 100 은 "기대 혼잡도 100" 이며, 산식 기준(정원 대비 여부)이 확인되기 전까지 "정원"이라고 부르지 않는다.

## 2. 왜 max 만으로 부족한가

| 경로 A | 경로 B |
|---|---|
| 한 구간만 140%, 나머지 60% | 120% 구간이 15분 연속 |
| max 140 → max 기준으로는 더 나쁨 | max 120 → max 기준으로는 더 좋음 |
| 100%+ 노출 2분 | 100%+ 노출 15분 |

max 는 "가장 붐비는 한 점"이고 exposure 는 "얼마나 오래 붐비는가"다. 사용자가 체감하는 것은 후자에 가깝다는 것이
설계 가설이며, 실측에서 두 기준이 26.2% 의 경우에 다른 경로를 골랐다. (위 표는 설명용 예시이며 실제 경로가 아니다.)

## 4. 앱 반영 (v2.1)

- 결과 카드 5번째 지표: "혼잡 주의 구간 N개" → **"100%+ 혼잡 노출 N분"** (도움말에 p90 값).
- 구간별 혼잡 곡선: 각 구간에 **도착하는 시각**의 값으로 그린다.
- 추천·대안·시간대안 판정은 v1 규칙 그대로, 값만 시간 진행형으로 다시 계산한다 (`yeoyuro_v2/app_bridge.py`, D-012).
- 시간대안 문구는 노출이 실제로 줄어들 때만 노출 변화를 함께 표시한다.

## 5. 한계

- 표본은 균등 무작위 OD, 평일 피크 부근 24개 시각이다. 수요 가중이 아니며 도시 전체 비율로 일반화하지 않는다.
- exposure 는 기대값(중앙값) 기준이다. 특정 날짜의 실제 노출이 아니다.
